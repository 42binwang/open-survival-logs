# WP-P0-14 — Interface pass 1 and the asset re-bake check

**Role:** architect. **Phase:** P0. **Depends on:** WP-P0-01 (merged), WP-P0-05 (material library). The gate scripts
are immutable after P0 except demonstrated-bug fixes approved by a reviewer, so the re-bake check has to land in P0.

## Scope
1. **Interface requests** from the lanes, frozen for P0:
   - `src/contracts/assets.js`: an optional top-level `library` in a manifest (the material library uses it), typed
     and validated.
   - **Material binding:** a lane binds a mesh part to a library material with per-object variation
     `{material, variant?, tint?, secondaryTint?, wear?, dirt?, seed?}` (P0-05 asked for it in
     `src/contracts/view.js`). Decide where it lives. Constraint: the view model stays sim-derived and
     render-agnostic, so a value nothing in the sim chooses belongs in the asset manifests (bindings) and the renderer
     (a stable seed per object id), not in the view model. Typedef, validation in `checkAssetManifest` (the material
     id resolves in the library; values in range), docs.
   - **Look constants** (from P0-04): the camera numbers in `docs/ART.md` that the renderer and the visual tools share
     — `{vfovDefault: 60, vfovMin: 40, pitchDeg: 40, yawDeg: 30, lookDistance: 10.47, cutWallHeight: 0.9, near: 1,
     far: 80}` — as a frozen module in `src/contracts/`, each value citing its ART.md section. (P0-04's review later
     moved `vfovMin` to 50, the source's native zoom stop; applied at merge #5.)
   - **Rebuild contract:** every shipped asset names how it is rebuilt from locked sources (per manifest entry or per
     family): the build entry under `tools/`, its arguments and its outputs, deterministic (fixed seeds, pinned tool
     versions, fixed Cycles seed and sample count).
2. **The asset-lock gate check** (§11: hashes match, and a 5% re-bake must match at SSIM ≥ 0.99):
   - `tools/asset-lock.mjs`, the gate's new `asset-lock` entry in place of `tools/fetch-assets.mjs --verify` (a
     one-line hook the integrator applies). It runs `fetch-assets --verify`, checks every shipped file in every
     manifest traces to locked sources and a build, then re-bakes a deterministic sample of at least 5% of shipped
     assets (at least one per family present; the seed is printed, `--all` and `--asset <id>` pick others) into a
     temp dir and compares each output with the committed file at SSIM ≥ 0.99.
   - Fingerprints per kind so SSIM applies to every asset: textures (KTX2 decoded, per channel, at least mip 0),
     images (PNG), meshes (a fixed-camera Workbench render through `tools/blender/run.sh`, plus exact triangle and
     bone counts), audio (a log-spectrogram image, plus duration and loudness within tolerance).
   - `tools/lib/ssim.mjs` (windowed SSIM on RGBA or grayscale) and `tools/lib/png.mjs` (PNG read and write with
     `node:zlib`), shared: WP-P0-11's visual regression uses the same SSIM.
   - `--json` in the gate's tool format `{ ok, summary, problems }`; exit 0 pass, 1 fail, 2 usage.
   - The material library adopts the rebuild contract through a hook patch the integrator applies; lanes still
     running adopt it from their package files.
3. `docs/ARCHITECTURE.md`: the material binding, the rebuild contract and the asset-lock check.

## Exclusive paths
`src/contracts/assets.js`, `src/contracts/view.js` and a new look-constants module in `src/contracts/` (this pass
only), the existing contract tests (extend, never
weaken), `tools/asset-lock.mjs`, `tools/asset-lock/`, `tools/lib/`, `tests/asset-lock.test.js`, `tests/fixtures/asset-lock/`,
the asset and contract sections of `docs/ARCHITECTURE.md`. Everything else, including `tools/gate/checks.mjs` and
`assets/materials/`, is a hook request.

## Read
Everything.

## Acceptance
- SSIM tests: identical inputs give 1; added noise and a shifted image lower it by the expected order; a reference
  fixture matches a published implementation within 1e-3.
- Fixture tests: a clean re-bake passes; a tampered texture (SSIM < 0.99), a file missing from the lock, a shipped
  file with no build and a hash mismatch each fail with the asset id named.
- `node tools/asset-lock.mjs --json` passes on master with the material library, re-baking at least one material;
  its run time is reported and fits the gate's 60-minute limit.
- The existing suite, typecheck and lint stay green.

## Deliverables
The files above on `wp/P0-14`, the hook patch for the gate entry and the material library, the JSON report.
