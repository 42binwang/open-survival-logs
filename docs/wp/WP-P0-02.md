# WP-P0-02 — Key registry and keys-audit (architect)

**Role:** architect. **Phase:** P0. **Depends on:** nothing (plain Node; no package.json needed).

## Scope
- `src/contracts/keys.js` (`// @ts-check`): every counter (`state.progress.counters[...]`), story tag
  (`state.story.tags`), flag (`state.story.flags`, `state.progress.taboo`, run/loop flags), bus event (`emit` / `on`)
  and save/storage key (localStorage keys, save-slot fields) declared once, with its meaning and owning package
  (use the owning module path for existing keys, e.g. `src/sim/explore.js`).
- `tools/keys-audit.mjs`: scans `src/` (static analysis of literal keys; template keys resolved against the registry
  patterns), and fails when a key is read but never produced, produced but never used, or used but not declared.
  Machine-readable output (`--json`) for the gate.
- `tests/keys-audit.test.js`: the audit logic on fixtures (a read-only key, a write-only key, an undeclared key).
- The current codebase must pass the audit. Where it does not (dead events, counters nobody reads, keys read that
  nothing writes), do **not** edit sim/UI files: list each as a hook request with the exact fix (remove the dead emit,
  add the missing producer, or declare the consumer), so the integrator can apply them.

## Exclusive paths
`src/contracts/keys.js`, `tools/keys-audit.mjs`, `tools/keys/`, `tests/keys-audit.test.js`.

## Read
Everything.

## Acceptance
- `node tools/keys-audit.mjs` lists zero problems once the hook requests are applied (report the count before and after).
- `node --test tests/*.test.js` stays green.

## Deliverables
The files above on `wp/P0-02`, the hook-request list, the JSON report.
