## Gaps

- **A08.** Two listed settings have no effect:
  - "Interface lag optimization" is saved (`game.settings.lagOptimization`) but nothing reads it. Wire it into `updateHud` in `src/ui/hud.js` (e.g. a longer rebuild throttle than 200 ms, and no rebuild during an inventory drag from `src/ui/invgrid.js`) and/or debounce `refreshWindows` in `src/ui/dom.js`.
  - Mouse side-button bindings are saved as `Mouse4`/`Mouse5` by `settingsWindow` (`src/ui/menus.js`), but pressing the button never triggers the action. `src/main.js` only compares `e.key` in `matches()`, and the canvas `mousedown` handler returns early for buttons 3/4. Move the keydown dispatch into a `runHotkey(action)` helper, and add a window `mousedown` listener that maps button 3/4 to the action whose `keyFor(action)` is `Mouse4`/`Mouse5`.
- **A12.** There is only one interactive element: the 📻 radio in `titleScreen` (`src/ui/menus.js`), which rotates and shows one of three toasts. The 08-21 and 09-02 notes add several interactive scene elements. Add at least one more clickable title-screen element with its own reaction in `titleScreen`.
- **A14.** Music selection is covered (`currentMood`), but playback is WebAudio-only, so SFX need a browser check. Many SFX hooks in `src/engine/audio.js` listen for bus events that nothing emits: `doorHit`, `doorDamaged`, `openingHit`, `furnDamaged`, `zombieAttack`, `zombieSpawn`, `zombieSpawned`, `hordeArrived`, `zombieGroan`, `chainsaw`, `chainsawHit`, `defenseHit`, `droneSent`, `droneLaunched`, `droneBack`, `thunder`. As a result, door bangs, chainsaws and thunder only come from the random `ambience()` poll. Emit these events from `src/sim/horde.js` (`hitOpening`, `hitDevice`, zombie spawns) and `src/sim/weather.js` (thunderstorm days).
- **B05.** Implemented in `src/main.js` and `src/render/iso.js`: dragging sets `cam.follow = false`, Space calls `game.ui.recenter`, and holding `,`/`.` sets `swivelTarget`, which springs back on key-up (matches the 09-08 note). `main.js` needs a canvas and `document` at import, so it can't run in Node. UI: needs browser check; only the default bindings are tested.
- **B07.** E never does "take all". `src/content/strings.js` labels the button "Take All (E)", and the 08-13 note describes E as "search and open, then E again to pick up". But the `interact` branch of the keydown handler in `src/main.js` only runs the hovered furniture's first enabled function, plus the explore/shop `interactKey` handlers. Export a `takeAll(state, fromInvId)` from `src/ui/panels.js` (the loop behind the storage panel's button) and call it from `main.js` when a storage, doorstep or floor window is open. The other hotkeys dispatch only in `main.js` (UI: needs browser check); their default bindings are tested.
- **C04.** Two listed effects are defined in `src/content/effects.js` but never applied:
  - Encumbered: add `set('encumbered', weightKg(backpack) > backpack.maxKg)` to `refreshAutoEffects` in `src/sim/stats.js`. Players can already go overweight: drags into the backpack, Take All and the doomsday rush pass `allowOverweight`.
  - Mental Block: it is only ever cured (by item 2410). Add a trigger, e.g. in `tickStats` (`src/sim/stats.js`) after Breakdown lasts some hours, and/or as an event effect in `src/content/events.js` (`effect: ['mentalBlock', hours]`).
- **D01.** Same Encumbered gap as C04. The grid and the kg limit are enforced, but going over the limit does nothing beyond the "Too heavy" label in the backpack panel.
