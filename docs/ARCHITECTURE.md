# Architecture

Plain ES modules: `index.html` loads `src/main.js`; Vite serves and builds them. Run with `npm run dev` (Vite on
127.0.0.1, port 5200 + the slot of the branch's work package in `docs/wp/STATUS.md`, 5200 on master; `PORT` or `WP_SLOT`
override it). Tests: `npm test` (`node --test tests/*.test.js`), syntax: `node tools/check_syntax.mjs`, types:
`npm run typecheck` (the files that start with `// @ts-check`), lint: `npm run lint`, browser: `npm run e2e`
(Playwright in Chromium, `tests/e2e/`). Every merge passes `npm run gate -- --quick` (`tools/gate.mjs`;
`npm run gate -- --status` shows the state of every check).

## Layers

| Layer | Path | Rules |
| --- | --- | --- |
| Game config | `src/data/gen/*.js` (generated by `tools/build_data.py`), `src/data/db.js` | Read-only. Chinese source text; localize with `loc(zh)` |
| Content | `src/content/*.js` | Hand-authored tables (homes, characters, shops, events, abilities, cards, strings) |
| Simulation | `src/sim/*.js` | Pure logic on a JSON-serializable `state`. No DOM. Must be testable in Node |
| Contracts | `src/contracts/*.js` | Frozen interfaces (`// @ts-check`, JSDoc types): the view model (`view.js`), the renderer interface and registry (`render.js`), the asset-manifest schema with material instances and the rebuild contract (`assets.js`), the camera look constants from `docs/ART.md` (`look.js`), the key registry (`keys.js`). Changed only through an interface request to the architect |
| 3D rendering | `src/render3d/` | The three.js renderer, the default with WebGL2: implements `src/contracts/render.js` and draws the *view* built by `src/ui/view.js` (see below) |
| Rendering | `src/render/iso.js` | Canvas isometric renderer (`?render=2d`; the fallback without WebGL2); draws the same view |
| UI | `src/ui/*.js` | DOM panels/HUD. Calls sim functions, never stores game data outside `state` |
| Wiring | `src/systems.js`, `src/main.js` | `src/systems.js` imports every system module so it self-registers; renderers register in `src/main.js` (the renderer switch: `?render=<id>` picks one) |

## State

`newGame(opts)` in `src/sim/state.js` builds the whole run. Everything persistent lives in `state`
(saved with `JSON.stringify`, keys starting with `_` are dropped). Key namespaces:

- `state.meta` — character (`wage` | `student` | `warehouse`), difficulty params, mode (`story` | `endless` | `pureEndless`)
- `state.phase` — `pre` (before outbreak), `post`, `dead`, `ending`
- `state.clock` — `t` game seconds since the loop start; `outbreakAt`; `speed` 0–3; `relaxed`. Helpers in `src/sim/time.js`
  (`dayNumber`, `hourOfDay`, `isNight`, `daylight`, `secondsUntilOutbreak`). Outbreak is 18:00 on the first day = Day 1.
- `state.player` — `stats {sat, sta, mor, life}`, `max`, `effects {id: {until, power}}`, `backpack` (inventory id),
  `money`, `scene` (`home` or `<prefix>:<id>`), `floor`, `x`, `y` (tile), `px`, `py` (smooth), `sleeping`, `daily` counters
- `state.actions` — `queue`, `current`, and `nextId`: action ids are `cancelAction` handles, so their counter is saved with the run
- `state.inventories` — `{ invId: { id, kind, w, h, maxKg, items: [inst] , cold, tag, owner } }` (see `src/sim/inventory.js`)
- `state.furniture` — `{ uid: { uid, cfg (Config_Furniture id or scenery key), slot, floor, x, y, w, h, hp, maxHp, reinforce, on,
  powered, inv, broken, data {} } }`. Per-system data goes in `f.data` (e.g. `f.data.plant`, `f.data.cook`, `f.data.fuel`)
- `state.home` — `{ id, slots: {slotId: uid|null}, unlocked: {floorOrLock: bool}, repairs }` (`src/sim/home.js`)
- `state.floorBoxes` — cardboard boxes on the floor `{ id, floor, x, y, inv }`
- `state.progress` — `prof {cook, plant, craft, trap, explore, defense: {lv, exp}}`, `counters` (achievement counters such as
  `cook.count`), `taboo` (challenge flags such as `meat`, `trade`, `explore`), `codexRun` (ids seen this run), `installed`
- `state.run` — per-loop run data: `cards` (planning card ids), `unlockedRecipes` (craft ids), `day`, `offers`
- `state.loop` — carried across rebirths: `planningPoints`, `abilities {id: lv}`, `memories`, `notes`, `cycle`, `bestDay`
- `state.crises` — `active: [{type, label, at, phase, show}]`, `upcoming: [...]` (shown in the crisis bar)
- `state.story` — `tags`, `quests`, `route`, `clues`, `commitAvailable {route: bool}`
- `state.zombies`, `state.weather`, `state.power`, `state.social`, `state.pre` (pre-disaster), `state.ui` (non-critical view state)

Global progress across runs (achievements, codex, unlocked characters, endings) is `game.history` (`src/engine/save.js`).

## Registries (how a system plugs in)

```js
import { registerSystem } from './tick.js';            // { id, order, init(state), ensure(state), tick(state, dt),
                                                        //   onHour(state, h), onDay(state, day), beforeOutbreak, onOutbreak, onDeath }
import { registerKind, enqueue } from './actions.js';   // action kinds: { canStart(state,a) -> true|reason, begin, progress(state,a,dt), complete, cancel }
import { registerScene } from './scenes.js';           // non-home scenes: { floor(state, floorId), blocked(state, floorId), stairs() }
import { registerObjectives } from './objectives.js';  // (state) => [{ text, prog, done, urgent, tip }]
import { registerSuggestions } from './suggest.js';    // (state) => [{ id, label, run() }]
import { registerPanel, openPanel } from '../ui/panels.js';   // (ctx) => opens a window via openWindow()
import { registerToolbarButton } from '../ui/hud.js';  // { label: () => str, key, panel, visible(state), dot(state) }
import { registerView } from '../ui/view.js';          // (state) => view for the renderer for a scene prefix
import { registerMenuButton } from '../ui/menus.js';   // title-screen buttons
import { emit, on } from '../engine/bus.js';           // events: 'toast' {text, kind}, 'openPanel' {panel, ...}, 'hour', 'outbreak', ... (src/contracts/keys.js)
import { registerRenderer } from './contracts/render.js';  // in src/main.js only: { id, label, create(canvas), isDefault, supported }
```

Actions: `enqueue(state, { kind, label, target: {furn: uid} | {x, y, floor}, dur (game seconds), cost {sta: 10}, gain {mor: 5},
max {mor: 1}, noWalk })`. The survivor walks to the target, works for `dur`, then `applyCostsAndGains` and the kind's `complete`
run. Costs are only charged on completion.

Furniture functions: `src/content/funcSpecs.js` maps every `Config_FurnitureFunc` id to a spec `{ kind, min, cost, gain, need,
give, panel }`. `kind: 'open'` opens `panel` via the bus. Subsystems register handlers for their kinds (e.g. `farm`, `generator`,
`drone`, `commit`). `furnitureFunctions(state, f)` lists what a piece offers; `startFurnitureFunction(state, uid, key)` queues it.

Materials at home: `homeSources(state)` = backpack + all installed storage inventories; `hasItems`, `consumeItems`, `giveItems`
in `src/sim/furnActions.js`; low-level `countIn`, `takeFrom`, `addItem`, `insert`, `moveItem` in `src/sim/inventory.js`.

Modifiers: `getMods(state)` (`src/sim/modifiers.js`) merges abilities, planning cards, character and difficulty. Call
`bumpMods(state)` after changing abilities/cards.

## Assets

Shipped assets live under `assets/<family>/` (binaries in git LFS) and are described by one manifest per family
(`assets/<family>/manifest.json`; the material library is `assets/materials/library.json`) in the schema of
`src/contracts/assets.js`; `checkAssetManifest` validates one and the gate's contracts check runs it on all of them.

- **Material binding.** The view model stays sim-derived and render-agnostic, so how an object is dressed is not in
  it. A model entry names the material of each mesh part in `materials` (`{material, variant?, tint?, secondaryTint?,
  wear?, dirt?, seed?}`, the material an entry of the library); a config binding (`bindings[cfgId]`) may override
  parts per config id. A renderer resolves `bindings[furniture.cfg]` → `resolveMaterials(entry, binding)` and seeds
  each part's variation with `instanceSeed(uid, part)` (FNV-1a of the view uid and the part), unless the instance pins
  a seed; the formulas for tint, variation, wear and dirt are the library's `library.conventions`.
  An instance may state its part's `use` (floor, wall, furniture, accent); a material's `params.tint.presetUse`
  restricts some presets to some uses, and an instance that picks a restricted preset must name a use it allows.
- **Rebuild contract.** Every shipped file can be rebuilt from locked sources. A manifest names its recipes in
  `rebuild` (`{entry, args, inputs, shared?, persist?, tools, seeds?, cycles?, cost, timeoutSec?}`: a script under
  `tools/`, its arguments with `{id}` / `{name}` / `{family}`, the repo paths it reads, pinned tool versions, fixed
  seeds and a Cycles seed and sample count when it renders with Cycles, and its expected seconds per asset); each
  entry names its recipe in `rebuild` and the SHA-256 of each of its files (`assetOutputs`) in `digests`.
- **Asset lock** (`node tools/asset-lock.mjs`, the gate's `asset-lock` check): locked sources verify
  (`tools/fetch-assets.mjs --verify`); every entry names a recipe, locked sources and matching digests; then a
  sample — at least 5 % and one asset per family, ranked by a seed (the commit's first 8 hex digits unless `--seed`;
  `--all`, `--asset <id>`) — is rebuilt in a sandbox copy of the checkout (`tools/asset-lock/sandbox.mjs`: inputs
  copied, `shared` paths linked, `persist` paths kept between runs) and every output is compared with the committed
  file by its fingerprint at SSIM ≥ 0.99 (`tools/lib/ssim.mjs`): textures by their decoded KTX2 level 0 per
  channel, images per channel, meshes by a two-view Workbench render plus exact triangle and bone counts, audio by a
  log-spectrogram plus duration (10 ms) and BS.1770 loudness (0.5 LU); other files byte for byte. For models it also
  checks that every pivot node exists in the glTF and that baked maps come with TEXCOORD_1 and TANGENT; the mesh render
  drops `KHR_texture_basisu` from `extensionsRequired` before Blender imports a glb (Blender cannot decode KTX2).
- **Model placement and dressing** (`ModelParams`, typed `params` of a model a slot holds): `slot` (a key of
  `SLOT_FOOTPRINTS`, the sim's slot types), `anchor` (`floor`: origin at the footprint's floor centre; `wall-face`: on
  the room side of the wall; `wall-center`: in the wall's centre plane, doors and windows), `front: '+z'` (the room
  side), `footprint` ([x, y] tiles, the slot's), `opening` for DOOR and WINDOW slots (`{widthM, headM, sillM?, leafM?,
  wallM}`, which the shell lane cuts), `pivots` (role → `{node, axis, openDeg}`: the door's `leaf` turns
  `leaf_hinge` about −Y by up to 90°), and `bake.uv: 1`. Baked `files.normal` / `files.occlusion` sit on TEXCOORD_1
  with TANGENT (MikkTSpace, OpenGL +Y); occlusion packs R = aoMap, G = convex curvature (the library's wear `c`),
  B = local occlusion (cavity = 1 − B). TEXCOORD_0 stays the meter UVs of the library materials. Variants may carry
  their own `lods`.
- **View facts for renderers.** A renderer reads facts from the view, never sim numbers it would re-derive. The home
  view states `home` (the home id), `powered` (`state.power.homePowered`: grid, generator or batteries),
  `lightsPowered` (`state.power.lightsPowered`: false when a shortage sheds the lights circuit) and `lightsSwitchedOff`
  (`state.power.lightsOff`, the power panel's light switch). The renderer owns ART.md's lamp schedule (lamps from
  17:00 while powered and not switched off); `lightsOn` stays the Canvas renderer's rule (night and powered). Entities
  carry the sim's own motion: `moving` and `heading` ([dx, dy] of the tile step) for the survivor's walk phase and a
  zombie's step, and the survivor's `action` (`{kind, phase, progress?}` of `state.actions.current`).
- **Damage states.** A model's `params.states` is an ordered rule list, `{variant, when, atMost?}`, the first match
  wins and the last rule is `always` (variant null: the entry's own files). `broken` matches `ViewFurniture.broken` or
  `data.breached`; `hpRatio` matches `ViewFurniture.hpRatio ≤ atMost`. The view builder sets `hpRatio` to
  hp / `effectiveMaxHp(f)` (reinforcement included), the sim's own measure, so a renderer never re-derives damage from
  hp and maxHp; `modelVariant(entry, piece)` applies the rules.
- **Audio** (`AudioParams`, the runtime audio convention of `docs/AUDIO.md`): `category` (sfx, ambience, ui, music,
  ir, test), `bus` (music, sfx, ambience, ui), `spatial` (a PannerNode at its world position), `loop`, `space` (the
  reverb it is played in; null when the space is baked in), `tags`, `pitchCents` / `gainDb` (± per play), `noRepeat`,
  `maxVoices`, `cooldown` (s); music `layer`, `bpm`, `meter`, `bars`, `barSeconds` (= 60 / bpm × beats per bar;
  layers switch on bar lines) and `loopEndSample` (= bars × barSeconds × sample rate, null if it does not loop); an ir
  its `space`, `rt60Bands` and `rt60`; a take variant its `levelDb`.
- **Frame cost.** `Renderer.stats()` returns `{drawCalls, triangles, gpuBytes}` for the last drawn frame (optional on
  the interface, required of the three.js renderer); the budgets tool samples it every frame and reads 0 as
  unmeasured. `gpuBytes` is `gpuBytes(inventory)` in `src/contracts/render.js`: every texture's mip levels (sides
  halved, floored at 1, rounded up to the format's blocks; `GPU_FORMATS` gives bytes per block, KTX2 counted as the
  format it was transcoded to) times its layers; every render target's colour attachments (× (samples + 1) with MSAA:
  the multisampled buffer and its resolve) plus its depth attachment (× samples); every buffer's byte length.
- **Look constants.** `src/contracts/look.js` freezes the camera numbers of `docs/ART.md` §1–§2 (FOV 60° → 50°,
  pitch 40°, yaw 30°, look distance 10.47 m, cut walls 0.9 m, near 1 m, far 80 m) for the 3D renderer and the visual
  tools.

## Conventions

- Text shown to players: config strings via `loc(zh)` / `itemName(id)`; authored strings via `pickLang({ en, zh })` inline or
  `tr(key)` for shared UI keys in `src/content/strings.js`.
- Randomness only via `src/engine/rng.js` (`rand(state)`, `chance`, `pick`, `weighted`) so saves are deterministic.
- Every system has Node tests in `tests/<system>.test.js` that build a state with `newGame({ seed })` and drive `tick(state, dt)`.
- Achievement counters are plain numbers in `state.progress.counters[key]` using the config counter names
  (e.g. `cook.count`, `cook.perfect`, `plant.harvest`, `trap.catch`, `zombie.kill`, `trade.active.dealcount`).

## The three.js renderer (`src/render3d/`)

| Module | Draws |
| --- | --- |
| `index.js` | `ThreeRenderer`: the camera from `src/contracts/look.js` (pitch 40°, yaw 30°, 10.47 m, FOV 60° → 50°), picking by raycast, the frame loop, `stats()` |
| `shell.js` | floors per room surface, walls on the centre lines of wall tiles with ART.md §1.3's cutaway, frames and glass, parapets, the street a storey below upper floors, and invisible key-light blockers (the floors above and the full wall volume) |
| `materials.js` | the KTX2 material library (`assets/materials/library.json`) with tint presets, the alpha tint mask and world-space macro variation |
| `props.js` | procedural models for every furniture family of the config (chosen from the Chinese name, as the Canvas renderer picks colours) |
| `models.js` | the scanned CC0 models of `assets/models/manifest.json` per family, fitted to the footprint |
| `furniture.js` | one prop per view piece, turned away from its wall, rebuilt only when its drawn state changes, merged per material, stocked by raycast shelf levels |
| `actors.js` | the survivor model with its twelve clips (idle, walk, run; work, use, eat, sit, sleep, attack; pickup, hit, death), the lying and sitting clips placed on the nearest bed or seat (`FurnitureLayer.rest`); zombies, raiders and neighbours as tinted clones; corpses |
| `dressing.js` | clutter, wall fixtures, rugs and litter from the scene's seed; frost in cold rooms; street markings, curbs, cones and leaves at sites; department signs, floor tape, gondolas and promo pallets in the pre-disaster shops |
| `blood.js`, `effects.js` | splats and pools where figures are hit and die (one instanced mesh); sparks, splinters, debris and dust at pieces the sim names, and the trading drone's flight (`renderer.effect`, forwarded from the bus by `main.js`) |
| `lighting.js` | ART.md §4.3's rigs with 45-minute blends, weather, room lamps, torch and fires; `FILL` is the fit to the side-by-side pairs |
| `post.js` | GTAO (normals rebuilt from the scene pass's depth, no second scene render), bloom, outlines, AgX, grade LUT v2, vignette, dither and the fade in after a floor or scene change (ART.md §5.3); quality follows the Graphics setting (`auto` is low on software rasterisers; `?quality=` overrides) |
| `surroundings.js`, `overlays.js` | the neighbourhood around the plot; Planning Mode slots, status markers and fire |

Tests: `tests/render3d.test.js` builds every scene headless; the `@smoke` e2e test and the side-by-side captures run it
in Chromium with hardware WebGL on macOS (`GPU_ARGS` in `tools/visual/capture.mjs`).
